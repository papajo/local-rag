## What the first eval run caught (3 real fixes, same day)

The first run scored **8/10**, and the failures were real, not test noise:

1. **Q9/Q10 answered when they should have declined (2 false answers).**
   The gate passed them on shared generic terms ("fee", "case",
   "deadline"). Fix: a refusal check — if the question asks for a value
   (fee / deadline / date) and the best passage says the documents do
   not contain that value, decline and quote that sentence as evidence.
   Q10 now declines with: "It does not state the deadline for any
   specific client's case." Q9 was also reworded: the original
   "fee for a criminal defence case" is actually answerable from the
   scope file ("It does not take on criminal defence…"), so the test
   was wrong, not the code — it is now "fee for a patent application",
   which nothing in the corpus covers.
2. **Faithfulness 0.75 (eval bug, not answer bug).** The harness keyed
   chunk text by source file, and several chunks share a file, so the
   dict kept only the last chunk. Fix: key by (source, chunk index).
   Faithfulness is now 1.00 — verified by substring match, not assumed.
3. **Q1 answered without showing the document list.** Two causes:
   (a) sentence cherry-picking across chunks pulled in an off-topic
   fee sentence for a documents question — fixed by switching to
   verbatim excerpts from the top chunks, in order; (b) chunking split
   the intro paragraph from its numbered list, and headings were not
   indexed, so the list chunk shared no terms with its own question —
   fixed by accumulating paragraphs under a heading into one chunk and
   prepending the heading to the indexed text. Q1 now returns the full
   5-item list with its citation, top score 1.00.

The threshold (`RELEVANCE_THRESHOLD = 0.35`) was **not** lowered to make
a question pass. All three fixes are in the code, and the full eval was
re-run from scratch after each one.
